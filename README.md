# 欲望国家シム（DESIRE NATION SIM）

プレイヤーは独裁者になり、法律ではなく「自分の欲望」を自由記述で宣言する。展開はポップなニュース仕立てで見せ、最後に欲望がどれだけ満たされたかを突きつける、国家運営の皮をかぶった自己診断ゲーム。


## Stack（最終スタック）

| レイヤー | 技術 | 理由 |
|---|---|---|
| 開発環境 | Expo Snack → ローカルExpo | 環境構築ゼロでブラウザから即実機プレビュー。詰まったらローカルに移行。 |
| 言語 | JavaScript | 型エラーで手を止めない。ハッカソンでは速度優先。 |
| 状態管理 | useState / useReducer | 一本道の進行なのでライブラリ不要。 |
| 永続化 | AsyncStorage（結果アーカイブのみ） | 進行中のセーブは持たないが、完了したプレイの結果だけ配列で保存し、あとから見返せるようにする。 |
| 画面遷移 | react-navigation不使用 | stage indexの切り替えのみで一本道を表現できる。 |
| AI連携 | Claude API（Haiku中心）を直接fetch | ネイティブ実行はCORS制約なし。サーバーを挟まず即動く。 |

画像生成・マルチプレイ・自由入力へのFunction callingは今回スコープ外。時間が余った場合の拡張候補として後述。

## Setup（環境構築）

`npx create-expo-app`相当の雛形（`package.json` / `App.js` / `app.json` / `index.js`）は作成済み。Snackを経由せず、最初からローカルExpoで開始している（詰まったときの避難先ではなく本線）。

- **Node.js 20系 / npm** — CI（[.github/workflows/ci.yml](.github/workflows/ci.yml)）もNode 20で揃えている
- **実機確認用にExpo Goアプリ**（iOS/Android）、またはシミュレータ/エミュレータ
- **Claude APIキー** — `.env`等で環境変数として渡し、リポジトリにはコミットしない（クライアントから直接fetchするため、公開ビルドでのキー露出に注意）

### 起動手順

```bash
git clone <このリポジトリ>
cd Dictator
npm install
npx expo start
```

- ターミナルに表示されるQRコードをExpo Goアプリ（iOS/Android）で読み取ると実機プレビューできる
- ブラウザで確認したい場合は起動後に`w`キー、またはコマンド`npx expo start --web`
- シミュレータ/エミュレータを使う場合は起動後に`i`（iOS）/ `a`（Android）キー

### もしローカルで詰まったら（Expo Snackへの退避）

ローカル環境構築がうまくいかない場合は、[snack.expo.dev](https://snack.expo.dev/) に`App.js`の中身を貼り付けるだけでブラウザ実機プレビューに切り替えられる（`components/` 以下など複数ファイルに分かれた分はSnack上に個別ファイルとして作成し直す）。

### ディレクトリ構成

- `components/` — UIコンポーネント（画面・表示部品）
- `api/` — Claude API呼び出し関数（`mapDesire.js` / `generateBeat.js` / `generateEnding.js`）
- `data/` — 欲望軸・プロンプト・履歴などの静的データ定義
- `game/` — メーター加算やエンディング判定などのゲームロジック

## Flow（画面 / 進行フロー）

1. **タイトル画面** — 「新規プレイ」→ 冒頭宣言へ／「過去の記録」→ 履歴一覧へ分岐
2. **冒頭宣言** — 自由記述で最初の欲望/法律を宣言する
3. **初日生成** — 宣言が組織にどう解釈されたかをニュース仕立てで表示
4. **1週間後生成** — 同上、事態が少し進行
5. **1か月後生成** — 物語のあとに欲望鑑定士の検診イベント（追加宣言 or スキップ）
6. **半年後生成** — 同上＋検診イベント
7. **1年後生成** — 同上＋検診イベント（最後の宣言）
8. **エンディング** — 世界の結末（見出し）→ 欲望メーター開示、の二段オチ → 結果をアーカイブに保存

## AI Calls（AI呼び出しの設計・3種）

### 1. 欲望マッピング（計4回：冒頭＋検診3回）

自由記述の宣言テキストを、隠し欲望軸への配点に変換する。

- 出力：JSONのみを返すよう指示 → `JSON.parse`
- 保険：パース失敗時は固定のフォールバック配点（例：全軸+1）を使う

### 2. 時系列ニュース生成（計5回：各節目）

累積した宣言と欲望メーターの動きを、表（ニュース見出し・つぶやき）と裏（側近メモ・独白）に仕立てる。

- 出力：`### NEWS` / `### MEMO` の固定マーカーで区切り、文字列split
- 保険：タイムアウト時は事前に用意した代替テキストを表示

### 3. エンディング生成（計1回）

最終メーターの傾向からエンディング型（強欲・空虚・破滅・皮肉な平和など）をアプリ側ロジックで決定論的に選び、その型の中身の文章だけAIに書かせる。

- 出力：型ごとに固定テンプレート＋AI生成の穴埋め
- 保険：型そのものは常に決まるので、文章生成が失敗しても進行は止まらない

全呼び出しにHaiku級モデルを使用（速度・コスト優先）。システムプロンプトには「男尊女卑」シナリオのfew-shot例を1本共通で埋め込む。

## Data（事前に決めておくデータ）

- **欲望軸** — 富・権力・名声・愛憎・快楽の5軸を提案（増やすほどマッピングとエンディング判定が複雑化する）
- **マイルストーン定義** — 初日／1週間後／1か月後／半年後／1年後のラベルと簡単な状況文
- **few-shot例** — 「男尊女卑」シナリオを`prompts.js`に定数として保持し、全呼び出しの共通システムプロンプトに埋め込む

## History（過去の結果を振り返る機能）

1プレイ中の進行状態そのものは保存しないが、完了したプレイの「結果」だけは端末に貯めていき、あとから見返せるようにする。

- **保存タイミング** — エンディング表示が完了した時点で1件を配列に追記する
- **保存する内容** — 日時／冒頭宣言の要約／最終的な欲望軸の値／選ばれたエンディング型と見出し
- **閲覧経路** — タイトル画面に「過去の記録」ボタンを追加 → 一覧（見出し＋日時）→ タップで詳細（当時のエンディング表示を再現）
- **上限** — 直近20件程度で古いものから削除し、肥大化を防ぐ

## Roles（役割分担）

| 担当 | 範囲 | 主なファイル |
|---|---|---|
| UI | ステージ送り、表裏切り替え表示、宣言入力フォーム、エンディング二段演出、履歴一覧・詳細画面 | `App.js` / `components/` / `components/History.js` |
| AI連携 | 3種の呼び出し関数の実装、パース処理とフォールバック | `api/mapDesire.js` / `api/generateBeat.js` / `api/generateEnding.js` |
| ロジック / データ | 欲望軸定義、メーター加算ロジック、エンディング型の判定条件、few-shot例文の執筆、結果アーカイブの保存・読込 | `data/axes.js` / `data/prompts.js` / `game/meter.js` / `data/history.js` |

## Safety Net（本番用の保険）

発表本番の回線不調やAPI遅延でデモが止まらないよう、各AI呼び出しにタイムアウトと固定フォールバック文を必ず用意する。デモ直前に一度通しでプレイし、そのとき生成された実際のテキストを「保険用の固定シナリオ」として保存しておくと、本番でネットが不安定でも進行だけは止まらない。

## Open（まだ決まっていないこと）

- 欲望軸の項目と数の最終決定
- 検診イベントの演出詳細（欲望鑑定士のキャラクター性など）
- 1プレイの長さ（体感プレイ時間の目標）
- AIプロンプトの詳細設計（トーン・文章量の調整）
- 宣言テキスト→軸マッピングの精度検証
